## Étapes de travail

### 1. Pourquoi setState ne suffit plus (15 min)

Avec `setState`, l'état est **local** au widget. Cela pose problème dès que :
- Plusieurs écrans ont besoin du même état (ex. : liste de tâches accessible depuis `HomeScreen` et depuis un widget de statistiques)
- La logique métier se mélange au code d'affichage dans les widgets

Le package `provider` résout ce problème en permettant de **séparer** la logique d'état de l'interface.

Lisez les deux premières sections de : https://docs.flutter.dev/data-and-backend/state-mgmt/simple

### 3. Création du TaskProvider (40 min)

Créez `lib/providers/task_provider.dart` :

```dart
import 'package:flutter/foundation.dart';
import '../models/task.dart';

class TaskProvider extends ChangeNotifier {
  final List<Task> _tasks = [];

  // Lecture seule depuis l'extérieur
  List<Task> get tasks => List.unmodifiable(_tasks);

  int get pendingCount => _tasks.where((t) => !t.isDone).length;

  void addTask(Task task) {
    _tasks.add(task);
    notifyListeners();
  }

  void toggleTask(String id) {
    final index = _tasks.indexWhere((t) => t.id == id);
    if (index != -1) {
      _tasks[index].isDone = !_tasks[index].isDone;
      notifyListeners();
    }
  }

  void deleteTask(String id) {
    _tasks.removeWhere((t) => t.id == id);
    notifyListeners();
  }

  void updateTask(Task updatedTask) {
    final index = _tasks.indexWhere((t) => t.id == updatedTask.id);
    if (index != -1) {
      _tasks[index] = updatedTask;
      notifyListeners();
    }
  }
}
```

> **À comprendre :** `notifyListeners()` déclenche la reconstruction de tous les widgets qui écoutent ce provider. C'est l'équivalent de `setState` mais à l'échelle de l'application.

> **Question :** Pourquoi `get tasks` retourne-t-il `List.unmodifiable(_tasks)` plutôt que `_tasks` directement ?

### 4. Enregistrement du Provider dans main.dart (10 min)

Enveloppez `MaterialApp` dans un `ChangeNotifierProvider` :

```dart
import 'package:provider/provider.dart';
import 'providers/task_provider.dart';

void main() {
  runApp(
    ChangeNotifierProvider(
      create: (_) => TaskProvider(),
      child: const MyApp(),
    ),
  );
}
```

### 5. Migration de HomeScreen (30 min)

Supprimez la liste `_tasks` et tous les `setState` de `_HomeScreenState`. Remplacez-les par des appels au provider.

**Lecture de l'état (avec rebuild automatique) :**
```dart
final taskProvider = context.watch<TaskProvider>();
final tasks = taskProvider.tasks;
```

**Actions (sans rebuild inutile) :**
```dart
context.read<TaskProvider>().toggleTask(task.id);
context.read<TaskProvider>().deleteTask(task.id);
```

**Mise à jour du compteur dans l'AppBar :**
```dart
AppBar(
  title: Text('Mes tâches (${taskProvider.pendingCount} restantes)'),
)
```

Si `HomeScreen` n'a plus de state, reconvertissez-le en `StatelessWidget`.

### 6. Migration de AddTaskScreen (15 min)

Dans `AddTaskScreen`, utilisez `context.read` pour ajouter ou mettre à jour une tâche sans lire l'état :

```dart
void _submit() {
  if (_formKey.currentState!.validate()) {
    final task = Task(
      id: widget.taskToEdit?.id ?? DateTime.now().millisecondsSinceEpoch.toString(),
      title: _titleController.text.trim(),
      description: _descriptionController.text.trim(),
      priority: _selectedPriority,
      isDone: widget.taskToEdit?.isDone ?? false,
    );

    if (widget.taskToEdit == null) {
      context.read<TaskProvider>().addTask(task);
    } else {
      context.read<TaskProvider>().updateTask(task);
    }

    Navigator.pop(context);
  }
}
```

> **À noter :** On utilise maintenant `Navigator.pop(context)` sans retourner de valeur — c'est le provider qui transmet l'information, plus la navigation.
