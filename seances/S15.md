# Séance 15 — Finalisation et préparation de la présentation

**Durée :** 2 heures  
**Travail :** individuel

---

## Objectifs pédagogiques

- Consolider et stabiliser l'application avant la présentation
- Identifier et corriger les bugs restants
- Compléter le journal de bord avec le bilan final
- Préparer et structurer la présentation orale

---

## Prérequis

- Séances 1 à 14 : toutes les fonctionnalités développées

---

## Étapes de travail

### 1. Checklist de qualité (30 min)

Parcourez chaque point et cochez ceux qui sont satisfaits. Pour chaque point non satisfait, décidez si vous le corrigez maintenant ou l'acceptez comme limitation connue.

#### Fonctionnalités

- [ ] Ajouter une tâche (titre obligatoire, description optionnelle, priorité, date d'échéance)
- [ ] Modifier une tâche existante
- [ ] Supprimer une tâche (par glissement, avec SnackBar annulable)
- [ ] Marquer une tâche comme complétée
- [ ] Filtres par onglets (Toutes / En cours / Terminées)
- [ ] Tri multi-critères (date, priorité, alphabétique, statut)
- [ ] Recherche plein texte
- [ ] Barre de progression globale
- [ ] Persistance SQLite (données conservées après fermeture)
- [ ] Notifications locales (si date d'échéance définie)
- [ ] Icône personnalisée visible sur l'émulateur
- [ ] État vide affiché quand la liste est vide

#### Qualité technique

- [ ] L'application ne plante pas lors d'une utilisation normale
- [ ] Aucune erreur rouge dans la console Flutter
- [ ] Le formulaire valide correctement les saisies
- [ ] La recherche fonctionne avec des mots partiels
- [ ] Les animations ne causent pas de saccades visibles

#### Code

- [ ] Pas de `setState` dans `HomeScreen` (géré par Provider)
- [ ] `dispose()` appelé sur tous les `TextEditingController`
- [ ] `if (mounted)` vérifié après chaque `await` suivi d'une action UI
- [ ] Pas de logique métier dans les widgets (séparation Provider / UI)

### 2. Correction des bugs prioritaires (30 min)

Concentrez-vous sur les bugs qui **impactent l'expérience utilisateur** lors de la démonstration. Un bug rare ou dans un cas limite peut être mentionné comme limitation connue lors de la présentation — c'est acceptable et honnête.

Documentez chaque bug corrigé dans votre journal de bord avec :
- La description du bug
- La cause identifiée
- La correction appliquée

### 3. Nettoyage du code (15 min)

- Supprimez les `print()` de débogage
- Supprimez le code de test ajouté en S11
- Vérifiez que les imports inutilisés sont supprimés (VS Code les signale en grisé)
- Vérifiez que `pubspec.yaml` ne contient pas de dépendances inutilisées

```bash
flutter analyze
```

Corrigez les warnings signalés par l'analyseur statique.

### 4. Complétion du journal de bord (15 min)

Remplissez la section **Bilan final** de `JOURNAL.md` :

```markdown
## Bilan final

### Ce que j'ai appris durant ce projet
- (Au moins 5 points concrets : widgets, concepts, patterns...)

### Ce que je ferais différemment si je recommençais
- (Architecture, choix techniques, organisation du temps...)

### Fonctionnalités que je n'ai pas eu le temps d'implémenter
- (Soyez honnête : quelles fonctionnalités sont manquantes ou partielles ?)
```

Exécutez `python journal.py` une dernière fois pour la séance 15.

### 5. Préparation de la présentation orale (20 min)

La présentation dure **10 minutes de démo + 5 minutes de questions**.

#### Structure suggérée (10 min)

| Durée | Contenu |
|---|---|
| 1 min | Introduction : présentation rapide de l'application |
| 5 min | Démonstration en direct des fonctionnalités |
| 2 min | Présentation d'un choix technique (ex. : migration SharedPreferences → SQLite, architecture Provider) |
| 2 min | Bilan : ce qui fonctionne, limitations connues, ce que vous referiez différemment |

#### Pour la démo

- Préparez un émulateur ou appareil avec quelques tâches déjà créées (dates, priorités variées)
- Testez la démo complète au moins une fois avant la séance 16
- Prévoyez un scénario de démonstration : ne naviguez pas au hasard

#### Pour les questions

Soyez prêt à expliquer :
- Pourquoi `StatefulWidget` vs `StatelessWidget`
- Ce que fait `notifyListeners()` dans le `TaskProvider`
- Pourquoi on utilise `context.read` vs `context.watch`
- Comment fonctionne la persistance SQLite
- N'importe quelle ligne de votre code

> **Rappel :** Vous serez interrogé sur des lignes précises de votre code. Un code que vous ne comprenez pas est un code que vous ne devriez pas avoir dans votre projet.

### 6. Dernier commit et vérification du dépôt (10 min)

```bash
flutter analyze          # 0 erreur, 0 warning
git status               # vérifier qu'il n'y a pas de fichiers oubliés
git add .
git commit -m "final: application complète, journal terminé, prête pour la présentation"
git push
```

Vérifiez sur GitHub que :
- Tous vos fichiers sont bien présents
- Le `JOURNAL.md` est complet (toutes les séances + bilan final)
- L'historique Git montre une progression régulière
